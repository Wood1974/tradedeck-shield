# Server job ticket (closed until a signing key is set)

While the phone has signal, and before its first photo for a ticket id (the job id, or `device`), it asks `POST /shield/tickets` for a ticket: the account, the ticket id, the server's clock and an expiry (7 days), signed by the server's ticket key. The phone countersigns with its hardware key (`signGenesis`: `shield-genesis-v1` followed by `SHA256(ticket_hash || canonical(clock))`) and posts it to `POST /shield/tickets/countersign`. The server checks its own signature, the account, the expiry and the phone's signature, then stores the start, once per account and ticket id (an exact replay answers `already`; a different second ticket for the same id is refused with 409 `ticket_already_started`). The phone then uses the ticket hash as the first record's `prev_hash` (`adoptServerTicket`).

- **Closed until `SHIELD_TICKET_SIGNING_KEY_PEM` is set** (a P-256 private key in PEM; `\n` is accepted for newlines). Closed means `503 tickets_closed` on the ticket routes; phones keep local tickets and uploads are unaffected. Generating the key and setting it on Render is the owner's step (it is a secret: nothing here creates or prints one), and setting it redeploys. `GET /shield/tickets/key` publishes the public key and its `kid` so anyone can check a ticket's signature.
- What it shows: a chain started with a server ticket began after the server's time on the ticket and no later than the time the server stored the countersign (`GET /shield/captures` shows `ticket: {origin: "server", after, before}`; otherwise `origin: "local"`, meaning nothing from the server anchors the chain's start, for example the phone was offline at the start, or an earlier record was not on the server when this one arrived). The phone's clock at countersign is the baseline the clock check uses for the first photo.
- What it does not show: who holds the phone's key, or that a photo is true. A ticket proves "not before", not when a photo was taken.
- Rotating the key: tickets signed with the old key are refused at countersign (`ticket_key_unknown`; the phone asks again). Starts already stored stay stored, but `GET /shield/tickets/key` shows only the current key, so keep the retired public keys somewhere a verifier can find them. Not built.

Server tickets (`app/tickets.py`) are closed until `SHIELD_TICKET_SIGNING_KEY_PEM` is set; the key is a secret only the owner creates and sets on Render.
