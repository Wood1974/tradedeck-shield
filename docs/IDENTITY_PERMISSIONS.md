# Identity & permissions
The token's `sub` is the account identity. In the deployed standalone mode (`SHIELD_API_AUTH_MODE=local`) that is a Shield account id from the server's own accounts; the Supabase JWT `sub` applies only to the `production` mode, which is not deployed. Job/point authorization is independently checked server-to-server. Evidence owner endpoints require the same account ID. Independent verification intentionally exposes only cryptographic verification facts. Admin health requires an explicit server-side allowlist.
